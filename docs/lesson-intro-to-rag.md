# Introduction to RAG: Helping AI Look Things Up

## What you will learn

In this lesson, you will learn what RAG is, why it is useful, and how it works, step by step. RAG stands for Retrieval-Augmented Generation. It is a way to help artificial intelligence (AI) tools give better answers. You do not need any technical background. By the end, you will be able to explain RAG to a friend using a simple example.

## First, what is a language model?

A large language model (LLM) is a computer program that has read a huge amount of text and learned which words usually come next. Chat assistants, like the ones you might talk to online, are built on LLMs. An LLM can write answers, explain ideas, and summarize text. It writes by guessing the most likely next word, one after another. But it does not look anything up while it writes. This detail is important for understanding why RAG is helpful.

## What is RAG?

RAG stands for Retrieval-Augmented Generation. The name has three parts:

- **Retrieval** means finding useful information.
- **Augmented** means improved by adding something.
- **Generation** means writing an answer.

So, RAG means: first find useful information, then use it to write a better answer. You can think of RAG as giving the AI an open-book exam instead of a closed-book exam.

## Why is RAG needed?

An LLM on its own has three common problems:

1. **Frozen knowledge:** It only knows what was in the text it learned from, so it does not know about anything that happened later.
2. **No private or recent documents:** It cannot see your school’s rules or your company’s handbook because it has never read them.
3. **Confident but wrong answers:** Sometimes, when it does not know something, it may still give an answer that sounds correct but is actually wrong. This is called a hallucination.

RAG helps with all three problems because the AI can read fresh, relevant information before it answers.

## What does retrieval mean?

Retrieval simply means looking something up. Imagine you have a big cookbook and want to know how long to boil an egg. You do not read the whole book. Instead, you use the index at the back to find the right page quickly and read only that part.

Retrieval in RAG works the same way. The system finds the few small pieces of text that are most likely to help answer the question.

## How is information retrieved?

To find the right information quickly, RAG breaks down documents into smaller pieces called **chunks**. Think of chunks like pages or paragraphs in a book.

Next, each chunk is turned into a special kind of code called an **embedding**. An embedding is a list of numbers that captures the meaning of the text. It’s like turning words into a secret code that shows what the text is about.

All these embeddings are stored in a big list, like a library catalog.

When you ask a question, the system also turns your question into an embedding (a secret code for your question).

Then, the system looks through the list to find the chunks whose embeddings are most similar to the question’s embedding. This is called **similarity search**.

To explain similarity search, imagine you have a box of colored balls, and each ball’s color represents a different meaning. You want to find balls that are closest in color to a ball you hold in your hand. The system does something similar but with numbers instead of colors.

Sometimes, instead of embeddings, a simpler method called **keyword search** is used. This looks for chunks that contain the same important words as the question, like searching for words in a text document.

## How does the AI use what it found?

After finding the most relevant chunks, the system adds these pieces of text to the question before sending it to the LLM. This added text is called **context**.

The LLM then reads the question along with this context and writes an answer based on the information it just read. This way, the AI can give answers based on fresh and specific information, not just what it remembers.

A good RAG system can also tell you where it found the information, so you can check the sources yourself.

## The complete RAG workflow

Here is the whole process from start to finish:

1. **Prepare:** Split the documents into chunks, turn them into embeddings, and store them.
2. **Ask:** A user types a question.
3. **Retrieve:** The system finds the chunks most related to the question by comparing embeddings.
4. **Augment:** The system adds those chunks to the question as context.
5. **Generate:** The LLM writes an answer using that context.
6. **Return:** The user receives the answer, ideally with links to the sources.

## A practical example: a school help desk

Imagine your school builds a chatbot that answers questions about school rules. The rule book is split into chunks and stored with embeddings.

A student asks: "Can I bring my phone to the exam hall?"

The system turns the question into an embedding and retrieves the chunk about exam-hall rules. That chunk says that phones must be switched off and left in bags.

The chunk is added to the question as context. The LLM then answers that phones must be switched off and kept in your bag during exams.

Without RAG, the chatbot would have had to guess, because it never read your school's rule book.

## Benefits and limitations

RAG has clear benefits:

- It lets an AI use up-to-date information and private documents without retraining the model.
- It makes answers more grounded, which reduces made-up answers.
- It can show its sources, which builds trust.

RAG also has limitations:

- If the retrieval step finds the wrong chunks, the answer will be poor.
- The extra steps add some cost and make answers a little slower.
- RAG reduces mistakes but does not remove them completely, so important answers should still be checked.

## Summary

- RAG stands for Retrieval-Augmented Generation: find useful information first, then write the answer.
- An LLM alone has frozen knowledge, cannot see private documents, and can be confidently wrong.
- Retrieval means looking up the most relevant pieces of text, like using a cookbook's index.
- Documents are split into chunks and turned into embeddings, which are numbers that capture meaning.
- The retrieved chunks are added to the question as context so the LLM can answer from them.
- RAG makes answers more current and grounded, but it is not perfect.
